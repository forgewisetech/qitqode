Большинство агентов для программирования забывают всё в тот момент, когда сессия заканчивается. QitQode — нет. Он читает и пишет код, выполняет команды, работает с Git — и хранит постоянную, доступную для поиска память о вашем проекте между сессиями, перестраивая собственный контекст, когда работа затягивается, чтобы продолжать двигаться вперёд, а не начинать заново.

Один аккаунт, восемь возможностей — **Free (no cost)**, **Adaptive**, **Fast**, **Economy**, **Planner**, **Repair**, **Max intelligence**. Конвейер **Orchestrated** — отдельная возможность Qortex для многоэтапного процесса gate → plan → build → repair, а не обычный интерактивный выбор модели. Никаких панелей управления провайдеров, никакой возни с API-ключами, никаких таблиц с расходами по каждой модели.

## Быстрый старт

```bash
npm install -g @qitqode/cli
# or: bun add --global @qitqode/cli

# Run
qitqode
```

При первом запуске вас проведут через вход:

- **Sign in with QitQode** — вход по коду устройства, который работает везде, включая SSH-сессии и удалённые песочницы: CLI показывает URL для подтверждения и код (и открывает браузер, если он доступен); подтвердите вход с любого устройства, чтобы завершить процесс
- **API key** — либо вставьте API-ключ QitQode

Затем выберите тариф в селекторе моделей и приступайте к работе. Это вся настройка.

### Использование QitQode на русском

TUI автоматически определяет системную локаль. Чтобы переключить язык вручную, выполните `/language` (или `/lang`) внутри QitQode и выберите «Русский» из списка.

## Почему QitQode

Вам не нужна ещё одна обёртка для чата. Вам нужен агент, который способен вести длительную задачу, не теряя нить. QitQode построен вокруг четырёх механизмов:

### 1. Память, которая переживает сессию

Каждый проект получает постоянный слой памяти на базе полнотекстового поиска SQLite: знания о проекте в `MEMORY.md`, автоматические контрольные точки сессий, черновые заметки и журналы прогресса по каждой задаче. При возобновлении работы нужная память подставляется автоматически — с ранжированием и учётом токен-бюджета, а не сваливается целиком. Агент продолжает с того места, где остановился, вместо того чтобы заново изучать вашу кодовую базу.

### 2. Контекст, который перестраивает сам себя

Длинные задачи выходят за пределы окна контекста. QitQode следит за окном, сохраняет состояние в контрольной точке до того, как оно заполнится, и восстанавливает рабочий контекст из последней контрольной точки, памяти проекта и прогресса задачи — так что многочасовой рефакторинг не обрывается на лимите токенов.

### 3. Автономность, с которой можно спросить

Задайте условие остановки командой `/goal`. Когда агент считает, что закончил, независимая модель-судья просматривает диалог и решает, действительно ли цель достигнута — никаких больше оптимистичных «всё готово!» на середине работы. В сочетании с древовидным трекером задач (`T1`, `T1.1`, …) и параллельными субагентами это даёт настоящую работу без присмотра.

### 4. Одна подписка, ноль возни с провайдерами

Семь интерактивных возможностей, один вход. Переключайте возможности прямо во время сессии командами `/free`, `/fast`, `/economical`, `/adaptive`, `/planner`, `/repair` или `/max-int`. Orchestrated — это отдельный многоэтапный конвейер Qortex, а не обычный интерактивный тариф. В любой момент проверяйте баланс во встроенном индикаторе qredits — расход прозрачен, а не оказывается сюрпризом в конце месяца.

### И то, что другие обычно оставляют за бортом

- **Учётные данные зашифрованы при хранении** — ваши токены аутентификации защищены ключом, который хранится в системном хранилище ключей ОС, а переменные окружения с учётными данными по умолчанию удаляются из каждого дочернего процесса, запускаемого агентом.
- **TUI, которым может пользоваться каждый** — режим для программ чтения с экрана, поддержка `NO_COLOR`, снижение анимации, управление детальностью объявлений и высококонтрастная тема с соответствием WCAG AA. Всё это встроено изначально, а не прикручено сбоку. (Подробнее ниже.)
- **Обычная лицензия MIT** — никакого отдельного файла с ограничениями на использование, никаких условий обслуживания, спрятанных в конце README.
- **Вход по коду устройства, рассчитанный на реальные машины** — работает по SSH, в контейнерах и в удалённых песочницах, где перенаправление на локальный браузер никогда бы не сработало.

## Основные возможности

### Несколько агентов

| Агент       | Описание                                                                    |
| ----------- | --------------------------------------------------------------------------- |
| **build**   | По умолчанию. Полные права на инструменты для разработки                     |
| **plan**    | Режим анализа только для чтения — исследование кода и проектирование решений |
| **compose** | Режим оркестрации для разработки по спецификациям и рабочих процессов на навыках |

Нажмите `Alt+M`, чтобы переключаться между основными агентами. Субагенты создаются системой по мере необходимости.

### Постоянная память

Межсессионная память на базе полнотекстового поиска SQLite FTS5:

- **Память проекта** (`MEMORY.md`) — постоянные знания о проекте, правила и архитектурные решения
- **Контрольная точка сессии** (`checkpoint.md`) — структурированные снимки состояния, которые автоматически поддерживает субагент checkpoint-writer
- **Черновые заметки** (`notes.md`) — временная область заметок для агентов
- **Прогресс задачи** (`tasks/<id>/progress.md`) — журналы по каждой задаче

Память подставляется автоматически при возобновлении сессии, поэтому агенту не нужно заново изучать контекст проекта.

### Умное управление контекстом

- **Автоматические контрольные точки** — решает, когда сохранить состояние сессии, исходя из окна контекста модели
- **Восстановление контекста** — когда контекст приближается к лимиту, он перестраивается из последней контрольной точки, памяти проекта, прогресса задачи и сохранённых недавних сообщений, чтобы агент мог продолжить текущую задачу
- **Подстановка по бюджету** — использует токен-бюджет, чтобы контролировать, сколько содержимого контрольной точки, памяти и заметок попадает в контекст, с ранжированием по важности

### Отслеживание задач

Древовидная система задач (`T1`, `T1.1`, `T1.2`, …), которая автоматически интегрируется с системой контрольных точек, поэтому прогресс задач сохраняется при возобновлении сессий.

### Система субагентов

Основной агент может создавать субагентов по требованию. Субагенты используют текущий контекст сессии и могут работать параллельно, с отслеживанием жизненного цикла, отменой и фоновым выполнением.

### Цель / условие остановки

Команда `/goal` задаёт условие остановки для сессии. Когда агент пытается остановиться, независимая модель-судья оценивает диалог и решает, действительно ли условие выполнено — предотвращая преждевременные «оптимистичные остановки» во время автономной работы.

### Режим Compose

Режим Compose предоставляет структурированный рабочий процесс для разработки по спецификациям. В него встроены навыки для планирования, выполнения, ревью кода, TDD, отладки, проверки и слияния — оркестрируя полный жизненный цикл от спецификации до готового кода.

### Предсказание запроса

Встроенные подсказки в виде «призрачного» текста предугадывают ваш следующий запрос по мере работы — нажмите `Tab`, чтобы принять.

### Глубокое исследование

Встроенный рабочий процесс `/deep-research` проводит структурированное многошаговое исследование для вопросов, которым недостаточно одного поиска.

### Headless-режим и работа из IDE

Запустите `qitqode serve` для headless HTTP-сервера или `qitqode acp` для поддержки Agent Client Protocol, чтобы управлять QitQode из совместимых редакторов и удалённых окружений.

**Запуски без присмотра.** Три флага определяют, как часто TUI останавливается, чтобы что-то спросить:

| Флаг | Вопросы | Разрешения инструментов |
| --- | --- | --- |
| `--never-ask` | решаются автоматически | по-прежнему запрашиваются у вас |
| `--fullauto` | решаются автоматически | подтверждаются автоматически, кроме явно запрещённого в конфигурации |
| `--headless` | решаются автоматически | подтверждаются автоматически — и без TUI; нужен `--prompt` или stdin |

`--fullauto` сохраняет обычный интерактивный TUI: вы видите ход сессии, а на промпте остаётся значок `FULL-AUTO`, пока разрешения выдаются за вас. Всё, что помечено как `deny` в конфигурации, по-прежнему отклоняется. `--fullauto` включает `--never-ask`, а вместе с `--headless` он безвреден (headless и так работает так же).

### Голосовой ввод

Потоковый голосовой ввод в реальном времени на базе TenVAD. Активируйте командой `/voice`, затем говорите — аудио разбивается по паузам и постепенно расшифровывается в поле ввода. Требуется `sox` (`brew install sox` на macOS, на других платформах аналогично) и явно настроенная модель распознавания речи через поле конфигурации `voice`.

> **Примечание:** модели для программирования доступны только по тарифам через бэкенд QitQode. Поле `voice` — это ограниченное исключение, используемое исключительно для распознавания речи и голосового управления; оно не добавляет модели в список моделей для программирования.


</details>

### Dream и Distill

- **`/dream`** — сканирует недавние трассы сессий, извлекает устойчивые знания в память проекта и удаляет устаревшие записи
- **`/distill`** — находит повторяющиеся ручные рабочие процессы в недавней работе и упаковывает наиболее уверенные кандидаты в переиспользуемые навыки, субагентов или команды

## Конфигурация

QitQode настраивается через `.qitqode/qitqode.json` в каталоге проекта (или `~/.config/qitqode/qitqode.json` глобально). Ключевые параметры:

- Выбор возможности модели (Free (no cost), Adaptive, Fast, Economy, Planner, Repair, Max intelligence и конвейер Orchestrated)
- Права агентов и пользовательские агенты
- Поведение контрольных точек и памяти
- Подключения серверов MCP
- Сочетания клавиш и тема

Max Mode (параллельное рассуждение best-of-N с выбором судьёй) можно включить через `experimental.maxMode` в конфигурации.

## Доступность

TUI QitQode поставляется с первоклассной поддержкой доступности:

- **Доступный режим** — задайте `QITQODE_TUI_ACCESSIBLE=1` (или `"tui": { "accessible": true }` в конфигурации) для работы, удобной программам чтения с экрана: линейный рендеринг главного экрана (без альтернативного экрана), без захвата мыши, низкая частота кадров, снижение анимации и без звуковых сигналов.
- **NO_COLOR** — любое непустое значение [`NO_COLOR`](https://no-color.org) переключает на монохромный рендеринг с прозрачным фоном. Уровень важности никогда не передаётся только цветом (уведомления несут символы `ℹ ✓ ▲ ✗`, диффы сохраняют маркеры `+`/`-`).
- **Снижение анимации** — задайте `QITQODE_REDUCE_MOTION=1` (или `"tui": { "reduce_motion": true }`), чтобы заменить спиннеры и анимации статическим текстом. Также переключается на лету из списка команд.
- **Звук** — отключите звуковые сигналы через `QITQODE_TUI_SOUND=0`, `"tui": { "sound": false }` или переключатель на лету в списке команд. Доступный режим всегда отключает звук.
- **Детальность объявлений** — в доступном режиме управляйте многословностью объявлений для программ чтения с экрана через `QITQODE_TUI_ANNOUNCEMENTS=quiet|normal|verbose`, `"tui": { "announcements": "quiet" }` или переключатель на лету в списке команд. `quiet` объявляет только границы ходов; `normal` (по умолчанию) добавляет строки о запуске инструментов; `verbose` добавляет строки о завершении инструментов. Ошибки и прерывания всегда объявляются на любом уровне.
- **Высококонтрастная тема** — выберите встроенную тему `high-contrast` для чисто чёрно-белых поверхностей с цветами, соответствующими WCAG AA.
- **Маленькие терминалы** — TUI корректно деградирует в узких терминалах и показывает понятное сообщение, когда окно меньше минимума 40x8.
- **Диалоги только с клавиатуры** — каждый диалог полностью управляется без мыши: `Esc` всегда закрывает, `Tab` (и клавиши со стрелками, если в диалоге есть ряд кнопок или список) перемещает фокус, а `Enter` или `Space` активирует элемент в фокусе. В обычных/NO_COLOR терминалах подсвеченная строка списка также несёт маркер `›`, чтобы выбор был различим без цвета.

Переменные окружения для доступности — это односторонние переключатели: `QITQODE_TUI_ACCESSIBLE=1`, `QITQODE_REDUCE_MOTION=1`, `NO_COLOR` и `QITQODE_TUI_SOUND=0` всегда имеют приоритет над значениями конфигурации и переключателями на лету — гарантии доступности нельзя отключить обратно. `QITQODE_TUI_ANNOUNCEMENTS` аналогично имеет приоритет над значением конфигурации и переключателем на лету, когда задан.
